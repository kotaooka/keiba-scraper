# 地方競馬 収集（Android版）

PC版（`keiba_scraper.py`）と同じデータを集めて、AI に貼り付けるテキストを作る Android アプリです。PC なしで動きます。

## 必要環境

- Android 10 以上

## インストール

1. スマホで次のリンクを開き、`keiba-collector.apk` をダウンロードする（ログイン不要）
   https://github.com/kotaooka/keiba-scraper/releases/download/android-latest/keiba-collector.apk
2. ダウンロードした APK を開いてインストールする（初回は「提供元不明のアプリ」の許可を求められる）

## 更新

右上の「⋮」→「このアプリについて・更新」で、今のバージョンと最新版を比べられます。新しい版があれば一覧の上にお知らせが出て、「更新する」でダウンロードからインストール画面まで進みます。初回だけ、端末の設定で「この提供元のアプリを許可」をオンにする必要があります。起動時の自動確認は6時間に1回までで、勝手に更新はしません。

- バージョンは `0.4.<ビルド番号>`。ビルド番号は GitHub Actions の実行番号で、`android/` を変更して push するたびに増える
- リリース `android-latest` には APK と `version.json`（版番号・コミット・ビルド日時・最近の変更）を置いている。アプリはこの `version.json` を読んで比べる
- 上のリンクから取り直して上書きインストールしても同じ（署名鍵を固定しているので上書きできる）。v0.3.0 以前には更新確認がないので、一度だけこの方法で入れ直す

## 使い方

### レース一覧
- 起動すると当日の開催一覧を読み込む。日付は「‹ ›」で1日ずつ、日付の部分をタップするとカレンダーで選べる
- 一覧のいちばん上で下へ引っ張ると読み直す
- 競馬場のタブを長押しするとお気に入り（★）になり、タブの先頭に並ぶ。前回見た競馬場は次に開いたときも選ばれている
- 当日は、次に発走するレースに「次」、発走までの時間（あと15分）が付く。30分を切ると色が変わる。発走済みのレースは薄く表示される
- レースをタップすると収集する。収集済みのレースは「✓ 収集済み」が付き、タップすると取り直さずに結果を開く（この端末のアプリ内に新しい順で40件まで保存）
- レースを長押しすると、通知・自動収集を設定できる（下記）

### 収集
出馬表 → 馬柱・過去5走 → 単勝・複勝 → ワイド → 三連複（上位人気一覧） → テキスト作成の順に進み、各段階の件数が出る（「中止する」で止められる）。1レースで30秒〜1分ほど（三連複を上位人気一覧から読めなかったときは、軸ごとの表を読むので1〜2分）。収集中は画面が消えないようにしている。

### 結果
- 終わるとテキストがコピーされる。画面の下に「送る」「コピー」「送り先」を固定している
- 「送る」は、最初だけ共有メニューで送り先のアプリ（Claude など）を選ぶ。2回目からはそのアプリへ直接送る。送り先を変えるときは「送る」を長押しするか「送り先」を押す
- 発走までの時間と、オッズを取ってから何分たったかを表示する。取ってから10分以上たっていて発走前なら「! オッズを更新」が目立つ色になる
- データの欠損は1行に畳んで表示する（タップで一覧）
- 各馬は馬番順・人気順で並べ替えられる。行をタップすると、性齢・斤量（前走比）・馬体重・脚質・前走間隔・乗替・条件別成績・持ち時計・騎手コンビと、過去5走の表（日付・場・距離・馬場・人気・着順/頭数・着差・上がり）が開く

### 通知・自動収集
レースを長押しするか、結果画面の「⏰ 通知・自動収集」で設定する。設定したレースには「⏰」が付く。

| 項目 | 時刻 | 内容 |
|---|---|---|
| 馬体重の発表ごろ | 発走の約1時間50分前 | 通知だけ |
| 発走20分前・5分前 | 発走の20分・5分前 | 通知だけ |
| 自動収集 | 発走の30分・20分・10分前から選ぶ | その時刻に1回だけ自動で収集し、終わったら通知する。通知をタップすると結果が開き、そのまま AI へ送れる |

- 初回は通知の許可を求められる
- 自動収集をアプリを閉じたまま動かすには、端末の設定で「アラームとリマインダー」の許可が要る（設定画面に案内のボタンが出る）。許可がないときは、時刻になったら「タップで収集」の通知を出す
- 通知は数分ずれることがある（端末の省電力のため）。端末を再起動しても予約は残る
- 自動収集はアクセス間隔・取得するページとも、画面から収集するときと同じ。画面からの収集と重なったときは自動収集を見送る

### 表示
画面の色は地方競馬に寄せている（ライトは昼の砂の馬場と内馬場の緑、ダークはナイターの照明の琥珀。レース番号は電光掲示板ふう）。右上の丸いボタンで「自動（端末のダークモードに合わせる）→ ライト → ダーク」の順に切り替わり、選んだ表示はアプリ内に保存される。

## 取得できなかったとき

収集中の画面の「取得中のサイトをプレビュー」（または右上の「⋮」）をオンにすると、画面の下半分に、アプリが裏で開いているページがそのまま見えます。プレビュー中は画面の下に帯が出て、どの画面からでも「閉じる」か戻るボタンで閉じられます。収集が成功すると自動で閉じ、失敗したときは原因を見られるよう開いたままにします。ページが表示されているのに取れない場合は、サイトの構造が変わっています。PC版の `debug_scraper.py` で構造レポートを作って直してください。

## PC版との対応

| PC版 | Android版 |
|---|---|
| `keiba_scraper.py` の解析・整形 | `app/src/main/assets/scraper.js`（同じ処理を JavaScript に移植） |
| `fetch_page`・`collect_race`（Playwright） | `Scraper.kt`（WebView） |
| 対話（`run.bat`） | `app/src/main/assets/ui.html`（画面）と `MainActivity.kt`（画面との受け渡し） |

- 解析を直したときは、`keiba_scraper.py` と `scraper.js` の両方を同じように直してください。指示文（`PROMPT_TEXT`）・期待値の下限（`EV_MIN`）・競馬場コードも両方にあります。
- 予想の記録と検証（`record`・`verify`）は Android版にはまだありません。PC版を使ってください。

## ビルド

`android/` 以下を push すると GitHub Actions が自動でビルドします（`.github/workflows/android.yml`）。手元でビルドする場合は Android Studio で `android/` を開きます。

`debug.keystore` はデバッグ版の署名を固定するための鍵で、パスワードは Android 標準のデバッグ鍵と同じ `android` です。秘密の鍵ではありません。

## 注意事項

ルートの README の注意事項がそのまま当てはまります。特に、連続実行・大量取得はしないでください。
